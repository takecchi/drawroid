# 北極星 — drawroid は何の代替か

> **人間が画像生成ツールの前に座り、プロンプトを書き、出てきた絵を見て、直して、また回す。**
> drawroid は、この「書く→見る→直す」のループを人間の代わりに AI が回すためのハーネスである。
> 人間は自然言語で「何が欲しいか」を伝え、最後に選ぶだけになる。

一文で言えば: **drawroid は「Stable Diffusion の前に座って試行錯誤する人間」の代替であって、「プロンプトを1回整形して投げるだけの変換器」ではない。**

この文書はプロダクトの全ての判断の基準（正典）である。実装・レビュー・設計の議論が迷子になったら、ここへ戻る。個別の要件はこの文書から導出され、[PRD.md](./PRD.md) 以下に規定される。矛盾したらこの文書が勝つ。

## 置き換えの対応

| 元の世界 | drawroid の世界 |
|---|---|
| 人間が頭の中で「こういう絵が欲しい」と思う | 人間が自然言語で依頼する（これは人間に残る） |
| 人間がプロンプト・モデル・LoRA・サンプラー等を選ぶ | **考える役**の LLM が選ぶ |
| 人間が出てきた絵を見て「ここが違う」と判断する | **見る役**の LLM（画像を読めるモデル）が判断する |
| 人間が「もういい」と手を止める | AI の判断、または人間が決めた上限で止まる |
| 人間が経験から好みを覚えていく | 好みを**記憶**としてファイルに溜め、次の依頼に効かせる |
| 人間が最後に気に入った1枚を選ぶ | これは人間に残る |

人間の役目は **何が欲しいかを伝えること・途中で口を出したければ出すこと・最後に選ぶこと** に縮む。

## 3つの原則（このプロダクトの憲法）

1. **ループは人間無しで回る** — 依頼を受けたら、止める条件に当たるまで「考える→生成→見る→次」を自分で回し続ける。人間の口出しは**いつでもできる**が、**無いと進まない**形にしてはいけない
2. **LLM に渡すトークンは最小** — 主対象はローカル LLM である。コンテキストは短く、推論は遅い。**1回の呼び出しに載せる量は、回数を重ねても増え続けてはいけない。** 履歴の全文再送・記憶の全文投入・原寸画像の投入・候補一覧の全件投入は、どれもこの原則への違反である
3. **全部見えて、全部止められる** — 何を考え、何を生成し、何を見てどう判断したかは、Web UI で人間が全部読める。人間はいつでも止められ、いつでも口を出せる。見えない判断・止められない処理を作らない

そして前提として:

- **ローカルで完結するツールである** — Docker も PostgreSQL も要らない。コマンド1つで起動し、データはファイルとして手元に残る。LLM と画像生成のバックエンドだけが外部（多くは同じマシンの別プロセス）である
- **LLM と画像生成バックエンドは差し替えられる** — ローカル LLM が主対象だが、OpenAI・Anthropic でも同じように動く。画像生成は Forge → A1111 → ComfyUI の順で対応する

## alteroid との違い（取り違えやすいもの）

drawroid は [takecchi/alteroid](https://github.com/takecchi/alteroid) を参考にして作るが、前提が違う所がある。alteroid の規則を**そのまま**持ち込まないこと。

| 論点 | alteroid | drawroid |
|---|---|---|
| トークン | 能力を削らないことが優先。上位モデルを惜しまない | **最小が第一の制約。** ローカル LLM の小さなコンテキストで回ること |
| 何を AI に許すか | 設定の一覧で権限を表すのは地雷（記憶で判断する） | **設定で決めるのが正しい形。** どのパラメータを AI が触ってよいかは人間が設定で決める |
| 実行基盤 | Claude Agent SDK をラップ | **AI SDK**（Vercel）。provider を問わない |
| 配置 | デーモン常駐・コンテナ・PostgreSQL | **単一プロセスのローカルツール。** ファイルのみ |

## 立ち戻るための問い（実装・レビューの冒頭で必ず問う）

- [ ] この変更のあとも、依頼してから止める条件に当たるまで、人間が何もしなくてもループが回り切るか？
- [ ] LLM への1回の入力が、ループの回数・記憶の量・バックエンドに入っているモデル数に**比例して**増えていないか？　増えるなら上限（文字数・件数の予算）で締めているか？
- [ ] 画像を LLM へ渡す前に縮小しているか？　同じ画像を2回以上渡していないか？
- [ ] 新しく足した判断・処理は、Web UI から人間が読めるか？　止められるか？
- [ ] 人間が触ってよいと許可していないパラメータを、AI が変えられる経路を作っていないか？
- [ ] 特定の LLM provider・特定の画像生成バックエンドの都合を、ループの中心に漏らしていないか？
- [ ] Docker・DB サーバ・常駐の外部サービスを、起動の前提に持ち込んでいないか？
- [ ] 人間が「好み」と言ったものを、記憶ではなくコードや固定のプロンプトに埋め込んでいないか？
