# マイルストーン — drawroid

各マイルストーンの**成果物・受け入れ基準・地雷**を持つ。要件の正本は [PRD.md](./PRD.md)、判断の基準は [north_star.md](./north_star.md) である。ここは「どの順で、何ができたら次へ進むか」を決める文書であって、要件を足したり緩めたりしない。

- マイルストーンは上から順に進める。前のマイルストーンの受け入れ基準を満たしてから次へ進む
- 1つのマイルストーンを複数の Issue / PR に分けてよい。分け方は実装者が決める
- 受け入れ基準のうち「実機で」と書いたものは、実際の Forge / A1111・ローカル LLM に繋いで確かめる。それ以外はスタブで自動テストにする
- **進捗はこの文書に書かない**（Issue と PR が持つ）

## M0 — 雛形と CI

**成果物**

- pnpm monorepo（`apps/*` と `packages/*`）。版は `mise.toml` で固定（Node 22 系 / pnpm）
- TypeScript（strict）・ESLint・Prettier・Vitest。設定は takecchi/alteroid に揃える
- `drawroid` コマンド: 1プロセスで Hono が HTTP API と Web UI（React Router v7 の SPA モード、`ssr: false`）の静的成果物を配信する。まだ中身は「起動した」だけでよい
- データディレクトリの初期化（既定はホーム配下。設定で変えられる）
- GitHub Actions の CI（typecheck・lint・format・test・build）
- `docs/architecture.md`（全体像・パッケージ構成・データディレクトリの構造・境界の置き場所）を実装者が書き、**人間の確認を通す**

**受け入れ基準**

- [ ] クリーンな環境で `pnpm install && pnpm build && pnpm drawroid`（または同等）で起動し、ブラウザで Web UI が開ける
- [ ] Docker・DB サーバ無しで起動する
- [ ] 既定で `127.0.0.1` のみで待ち受け、ポートが 7860 / 8188 と衝突しない
- [ ] CI が PR で走り、**draft の PR では走らない**。draft から ready にした時点で走る（`types` に `ready_for_review` を含める）
- [ ] 同じ PR / 枝に新しい push が来たら、古い run は取り消される（**後勝ち**。`concurrency` + `cancel-in-progress`）
- [ ] `docs/architecture.md` が人間の確認を通っている

**地雷**

- draft を除外する `if:` を足して `ready_for_review` を `types` に入れ忘れると、draft から ready にしても CI が1本も走らない
- `main` への push の run まで取り消す設定にしない（取り消すのは PR の run だけ）

## M1 — Forge で1枚生成する

**成果物**

- 画像生成バックエンドの境界（差し替え可能なポート）と、**Forge** のアダプタ
- バックエンドから候補（チェックポイント・LoRA・サンプラー・スケジューラ等）を取得する
- パラメータを明示して1回生成する API。結果（画像・パラメータ・バックエンドの応答のメタデータ）をファイルに保存する
- Web UI: パラメータを手で入れて生成し、結果を見る最低限の画面

**受け入れ基準**

- [ ] スタブのバックエンドに対して、生成・保存・取得がテストで通る
- [ ] **実機で**: Forge に繋いで1枚生成し、データディレクトリに画像とメタデータが置かれ、Web UI で見られる
- [ ] Forge が落ちている・URL が違うとき、原因が分かるエラーが UI に出る
- [ ] 保存中にプロセスを殺しても、壊れた JSON が残らない

**地雷**

- Forge 固有の形（エンドポイント・フィールド名）をアダプタの外へ漏らさない。M6 で A1111、将来 ComfyUI を足すときに中心を書き換えることになる

## M2 — LLM でループを回す

**成果物**

- AI SDK による LLM 接続。provider: OpenAI 互換（Ollama・LM Studio 等）・OpenAI・Anthropic
- 役割（考える役・見る役）ごとの provider / モデル設定。既定は同じモデル
- ジョブ: 自然言語の依頼 → 考える → 生成 → 見る → 次へ、のループ
- 止める条件: AI の判断・回数上限・時間上限・人間の停止。止まった理由の記録
- 状態の要約による持ち回し、画像の縮小
- 全ての LLM 呼び出しの記録（入力・出力・トークン数・所要時間）
- ジョブの待ち行列（生成は直列）と、プロセス再起動後の再開
- この段階での AI の可動範囲は **プロンプト・ネガティブ・seed・ステップ・CFG** まででよい（残りは M4）

**受け入れ基準**

- [ ] スタブの LLM とスタブのバックエンドで、依頼から「AI の判断で止まる」「回数上限で止まる」「人間が止める」の3通りがテストで通る
- [ ] **回を N 回重ねても、「考える」「見る」への入力の長さが上限を超えないこと**をテストで保証する（例: 1回目と 30回目の入力長が同じ予算内）
- [ ] 見る役に渡す画像は縮小されている。同じ画像を2回渡していない（テストで保証）
- [ ] 構造化出力が壊れて返ってきたとき（スキーマ不一致）、再試行し、それでも駄目ならジョブをエラーとして止めて理由を残す
- [ ] プロセスを途中で殺して起動し直すと、ジョブが続きから再開する
- [ ] **実機で**: ローカル LLM（画像入力対応のもの）と Forge で、自然言語の依頼から3回以上ループが回って止まる。各呼び出しのトークン数が記録されている
- [ ] **実機で**: provider を OpenAI または Anthropic に切り替えても同じ依頼が回る

**地雷**

- 過去の回の評価・プロンプトを配列で積み増して毎回渡す（いちばんやりがちで、いちばん北極星を壊す）
- provider ごとの分岐をループの中心に書く（AI SDK の境界で吸収する）
- 「ローカルモデルは構造化出力が苦手だから」とスキーマ検証を外す（検証して再試行する）

## M3 — Web UI で見て、止めて、口を出す

**成果物**

- ジョブ一覧（走行中・待ち・終了）とジョブ詳細（各回の画像・パラメータ・考える役の決定・見る役の評価と理由・口出し・止まった理由）
- 依頼の投入画面。止める条件を**自然言語でも専用フォームでも**指定でき、自然言語の変換結果を確認・修正してから開始できる
- 停止・口出し（次の回から反映）
- 参照画像の添付（依頼時・口出し時）。添えた画像は M2 までの可動範囲では「見る」の比較対象・「考える」の材料として使い、img2img / ControlNet の元にするのは M4 から
- 最終選択（お気に入り・却下）
- LLM 呼び出しの記録の閲覧（ジョブごと・回ごとのトークン数と時間。中身も読める）
- SWR のポーリングによる更新

**受け入れ基準**

- [ ] 上の操作がすべて HTTP API の上に乗っている（画面だけにある経路が無い）
- [ ] 口出しは生成中の1枚を止めず、次の回の「考える」に反映される。記録上「人間の指示」として AI の判断と区別して表示される
- [ ] 口出しを何回しても、「考える」への入力の長さが予算を超えない（原文を積み増していない）
- [ ] 止める条件を走行中に変更できる
- [ ] 参照画像は縮小されて1度だけ LLM に渡り、以後はテキストの要点で持ち回される（テストで保証）
- [ ] **実機で**: 依頼の投入から最終選択まで、Web UI だけで完結する

## M4 — AI が触れるパラメータを広げ、設定で許可する

**成果物**

- 可動範囲の拡大: チェックポイント・VAE・LoRA（種類と重み）・サンプラー・スケジューラ・解像度・Hires. fix・img2img・inpaint・ControlNet
- パラメータごとの許可設定（AI に任せる〔候補の絞り込み付き〕/ 固定 / 使わない）。全体の既定値とジョブごとの上書き
- LoRA 等への人間の短い説明の付与
- Web UI: ある回の画像の上に inpaint のマスクを塗り、口出しとして渡す画面
- バックエンドで使えないもの（拡張が無い等）の検出と、UI での理由表示

**受け入れ基準**

- [ ] 許可していないパラメータは、AI の出力スキーマにそもそも含まれない（テストで保証）
- [ ] 「固定」にしたパラメータは、AI が何を返してもその値で生成される
- [ ] LoRA が数百個ある状態でも、LLM に渡す候補の一覧は予算内に収まる（テストで保証）
- [ ] **実機で**: チェックポイントと LoRA を AI に選ばせた依頼が回る
- [ ] マスクが無い状態では inpaint が AI の選択肢に含まれず、ループはマスクを待たずに進む（テストで保証）
- [ ] **実機で**: 前の回の画像を元にした img2img がループの中で使われる
- [ ] **実機で**: 人間が添えた参照画像を元にした img2img または ControlNet がループの中で使われる
- [ ] **実機で**: 人間が UI で塗ったマスクで、次の回に inpaint が行われる

**地雷**

- 候補一覧を全件 LLM に流す
- inpaint のために人間のマスクを待ってループを止める
- ControlNet / inpaint の引数の形をアダプタの外へ漏らす

## M5 — 好みの記憶

**成果物**

- ジョブ終了時の蒸留（依頼・口出し・選択・却下・止まった理由から、好みの短い項目を作る / 既存の項目を更新する）
- 依頼に関係する記憶だけを選んで「考える」「見る」に渡す仕組みと、その文字数予算
- Web UI: 記憶の一覧・閲覧・編集・削除。どのジョブから学んだかが辿れる

**受け入れ基準**

- [ ] 記憶はファイルに置かれ、人間がファイルを直接直しても反映される
- [ ] 記憶が数百項目あっても、1回の呼び出しに載る量は予算内に収まる（テストで保証）
- [ ] 予算で落とした項目が記録に残る
- [ ] **実機で**: 「指の崩れは許容しない」と口出ししたジョブのあと、別の依頼でその好みが「見る」の評価に効いている

## M6 — A1111 対応

**成果物**

- **A1111** のアダプタ。Forge との差（エンドポイント・使えるパラメータ・拡張）を吸収する
- 設定でバックエンドを選べる

**受け入れ基準**

- [ ] M1〜M5 のスタブのテストが、A1111 のアダプタでも通る
- [ ] **実機で**: A1111 に繋いで、M2 の実機の受け入れ基準と同じ依頼が回る
- [ ] ループの中心（考える・見る・状態・記憶）のコードに変更が要らなかった（要ったなら、それは M1 の境界の欠陥として直す）
