# PRD — drawroid

## 背景・課題

Stable Diffusion で狙った絵を出すには、試行錯誤が要る。プロンプトを書き、生成し、見て、「手が崩れた」「もっと明るく」「この LoRA は強すぎる」と判断し、直してまた回す。1枚が数秒〜数十秒で出てくる以上、**ボトルネックは GPU ではなく、席に座って見て直す人間**である。

その判断の大半は「何が欲しいか」と「その人の好み」を知っていれば下せる。そして今は、画像を読める LLM がローカルでも動く。ならば「書く→見る→直す」のループを LLM に回させ、人間は依頼と最終選択だけをすればよい。

## プロダクトの目的

**「人間が画像生成ツールの前で試行錯誤する」— これを人間の代わりに AI が行えるようにする**（正典: [north_star.md](./north_star.md)。この PRD の要件はすべてそこから導出される）。

そのために、自然言語の依頼から「考える→生成→見る→次」のループを自律で回すハーネスを、**手元の端末でコマンド1つで起動できるローカルツール**として提供する。

## 提供価値（コア4点）

LLM 呼び出しは自作せず **AI SDK** を使う。画像生成は既存のバックエンド（Forge / A1111 / ComfyUI）の API を叩く。drawroid の独自価値は次の4点に絞る。

1. **自律ループ** — 依頼から、止める条件に当たるまで人間無しで回る
2. **トークン最小の設計** — ローカル LLM の小さなコンテキストで、何十回回しても1回の入力が膨らまない
3. **好みの記憶** — 口出し・選んだ絵・却下した絵から好みを蒸留し、次の依頼に効かせる。人間がいつでも読んで直せる
4. **見えて、止められて、口を出せる Web UI** — 稼働状況・各回の画像・判断の理由が全部見える

## 要件: ループ

1回の依頼（**ジョブ**）は、次の**回**（イテレーション）の繰り返しである。

1. **考える** — 考える役の LLM が、依頼・現在の状態（要約）・前回の評価・人間の口出し・関係する記憶から、次の生成パラメータを決める。出力は構造化した短い形（スキーマで検証できるもの）
2. **生成** — 画像生成バックエンドへ投げる。1回で複数枚（バッチ）を出してよい
3. **見る** — 見る役の LLM が、縮小した画像と依頼の要点を見て評価する。出力は構造化した短い形（意図にどれだけ合っているか・問題点・次に変えるべきこと・止めてよいか）
4. **次へ** — 止める条件に当たっていなければ 1 へ戻る

- **状態は要約として持ち回す。** 回を重ねても「考える」への入力は、依頼の要点・現在の最良候補とその評価・直近の評価・未反映の口出し・記憶の抜粋だけで構成する。過去の回の全文は渡さない（[トークン](#非機能要件-トークン最小)）
- **ジョブは中断・再開できる。** プロセスが落ちても、ファイルに残った状態から再開できること
- 生成バックエンドは GPU を1枚と仮定し、**生成は直列に1つずつ**行う。複数のジョブは待ち行列に入る

### 止める条件

止め方は2系統あり、**両方に対応する**。どちらを使うか・上限をいくつにするかは、人間がジョブごとに決める。

- **AI の判断で止める** — 見る役が「意図どおり」と判断したら止める
- **上限で止める** — 回数・経過時間・生成枚数などの上限
- **人間が止める** — いつでも（Web UI・API）

指定の方法は2つあり、どちらでもよい:

- **自然言語** — 「10回まで」「いい感じになったら止めて、最大30分」。LLM がこれを構造化した設定に変換し、**変換結果を人間に見せて**確認・修正できるようにする
- **専用 UI** — フォームで直接指定する

**止まった理由**（AI の判断・どの上限・人間の停止・エラー）は記録に残し、UI に出す。

### 口出し（途中での介入）

- 人間は走行中のジョブにいつでも自然言語で口を出せる（「もっと明るく」「LoRA を外して」）
- 口出しは**次の回の「考える」から**反映する。生成中の1枚は止めない
- 口出しは記録に「人間の指示」として残し、AI の判断と区別して表示する
- 口出しの原文を履歴として積み増して LLM に渡さない。**依頼の要点（要約済みの意図）へ統合**してから渡す
- 止める条件の変更も口出しの一種として受け付ける

### 参照画像

- 人間は依頼に画像を添えられる。走行中の口出しにも添えられる
- 参照画像は img2img・ControlNet の元にできる。何に使うか（構図・ポーズ・色味など）は人間が言葉で添えてよく、無ければ考える役が決める
- 参照画像を見る役に渡すときも縮小し、1度だけ渡す。以後は「参照画像の要点」のテキストで持ち回す

### 最終選択

- ジョブの終了後（および途中でも）、人間は気に入った画像を選べる（お気に入り）・却下できる
- 選択と却下は記憶の材料になる（[記憶](#要件-好みの記憶)）

## 要件: AI が触れるパラメータ（設定で許可する）

AI はプロンプト以外も選べる。対象は少なくとも次のもの:

- プロンプト / ネガティブプロンプト
- チェックポイント（モデル）・VAE
- LoRA（種類と重み）
- サンプラー・スケジューラ・ステップ数・CFG・seed
- 解像度・Hires. fix
- img2img（元画像・denoising strength）
- inpaint
- ControlNet

元画像の出どころは、前の回の生成画像か、人間が添えた参照画像（[参照画像](#参照画像)）である。

- **inpaint のマスクは人間が Web UI で塗る。** 人間がある回の画像の上に塗ったマスクを口出しとして渡すと、AI は次の回からそのマスクで inpaint を使える
- **AI はマスクを待って止まらない。** マスクが無ければ inpaint は選択肢に入らないだけで、ループは他の手段で進む（[北極星の原則1](./north_star.md#3つの原則このプロダクトの憲法)）

**何を AI に許すかは設定で決める。** パラメータごとに次のどれかを選べること:

- **AI に任せる**（必要なら候補を絞る: 例「この3つのチェックポイントの中から」）
- **固定する**（人間が値を決め、AI は変えない）
- **使わない**

設定には全体の既定値があり、ジョブごとに上書きできる。**許可していないパラメータを AI が変える経路を作らない**（スキーマの段階で、許可したものだけを AI の出力に含める）。

- 候補（チェックポイント・LoRA・サンプラー等）の一覧はバックエンドから取得する
- **候補を LLM に渡すときは全件を流さない。** 許可されたものだけを、件数・文字数の予算内で渡す（LoRA が数百個ある環境を想定する）
- LoRA など名前だけでは用途が分からないものには、人間が短い説明を付けられる。説明は LLM に渡す材料になる

## 要件: 好みの記憶

- 会話（依頼・口出し）と結果（選んだ絵・却下した絵・止めた理由）から、人間の**好み**を蒸留して記憶に溜める（例:「アニメ調は○○のチェックポイントが好き」「指の崩れは許容しない」「彩度は控えめ」）
- 蒸留はジョブの終了時に行う
- 記憶は**ファイルに置き**、人間が Web UI からいつでも読めて、直接書き換え・削除できる（信頼の要件）
- **トークンの制約を設計の前提にする:**
  - 記憶は短い項目の集まりとして持つ（長文の自由記述にしない）
  - LLM には全文を渡さず、**その依頼に関係する項目だけ**を選んで渡す
  - 1回の呼び出しに載せる記憶の量には文字数の予算を設ける
  - 予算を超えたことは隠さず記録する（何を落としたか分かるように）

## 要件: LLM（provider と役割）

- LLM 呼び出しは **AI SDK** を使う。対応する provider は少なくとも:
  - **OpenAI 互換 API**（Ollama・LM Studio・llama.cpp server 等。**主対象**）
  - OpenAI
  - Anthropic
- 役割は次の2つで、**役割ごとに provider とモデルを設定できる**。既定は両方同じモデル
  - **考える役** — 依頼の解釈・パラメータの決定・止める条件の変換・記憶の蒸留
  - **見る役** — 画像の評価。**画像入力に対応したモデルが必須**
- モデルの能力差（構造化出力・tool calling・画像入力の有無、コンテキスト長）を吸収する。構造化出力に弱いローカルモデルでも、検証と再試行で回ること
- API キー等の秘密は設定ファイルまたは環境変数で受け取り、ログ・UI・LLM の入力に出さない

## 要件: 画像生成バックエンド

- 優先順位は **Forge → A1111 → ComfyUI**。当面のスコープは Forge と A1111
- バックエンドは差し替え可能な境界の向こうに置く。**ループの中心はバックエンド固有の形を知らない**
- バックエンドで使えないパラメータ（例: ControlNet 拡張が入っていない）は、AI の選択肢から外し、その理由を UI に出す
- 接続先 URL は設定で変えられる

## 非機能要件: トークン最小

[北極星の原則2](./north_star.md#3つの原則このプロダクトの憲法) の具体形。

- **1回の LLM 呼び出しの入力は、ループの回数に比例して増えない。** 回を重ねても上限が一定であることを、テストで保証する
- **画像は縮小してから渡す。** 縮小後の長辺は設定で決められる（既定は小さめ）。同じ画像を2回以上渡さない（評価済みの画像は評価結果のテキストで持ち回す）
- **出力も短くする。** 構造化した短い形を求め、長い自由記述（思考の垂れ流し）を求めない
- **システムプロンプトを太らせない。** 機能を足すたびに指示文を足す形にしない
- 使うモデルのコンテキスト長を設定でき、それを超えない入力を組み立てる
- **全ての LLM 呼び出しについて、入力・出力のトークン数と所要時間を記録し、UI で見られる**こと（測れないものは減らせない）

## 非機能要件: ローカルで完結する

- **Docker・PostgreSQL・常駐の外部サービスを要求しない。** Node.js だけで起動する
- `drawroid` コマンド1つで起動し、1つのプロセスが HTTP API と Web UI を両方配信する
- 既定では `127.0.0.1` だけで待ち受ける。待ち受けのポートは、Forge / A1111（7860）・ComfyUI（8188）と衝突しない値を既定にする
- **データはファイルのみ**に置く。置き場所は設定で変えられる（既定はユーザーのホーム配下）
  - ジョブ・回・画像・メタデータ・記憶・設定が、人間がディレクトリを開いて読める形で置かれている
  - 書き込みは原子的に行い、途中で落ちても壊れた JSON を残さない
  - ジョブのディレクトリを消せばそのジョブは消える（隠れた索引に依存しない）

## 要件: インターフェース（Web UI・HTTP API・CLI）

- **Web UI が主な入口**である。全ての操作は HTTP API の上に乗り、Web UI はその API を使う（画面だけにある経路を作らない）
- Web UI でできること:
  - **依頼の投入**（自然言語。参照画像を添えられる。止める条件・許可するパラメータもその場で指定できる）
  - **稼働状況の閲覧** — 走行中・待ち行列・終わったジョブの一覧。ジョブごとの各回の画像・パラメータ・見る役の評価と理由・考える役の決定・人間の口出し・止まった理由
  - **停止**・**口出し**（参照画像を添えられる。inpaint のマスクを画像の上に塗って渡せる）
  - **最終選択**（お気に入り・却下）
  - **記憶の閲覧と編集**
  - **設定**（LLM の provider と役割・バックエンド・パラメータの許可・予算）
  - **LLM 呼び出しの記録**（トークン数・所要時間。中身も読めること — デバッグのため）
- 更新は **SWR のポーリング**で反映する（1回の生成に数秒〜数十秒かかるので即時性は要らない）
- CLI は起動のためのもの（`drawroid` / 主要な設定の指定）。CLI でジョブを操作できることは必須ではない

## ターゲットユーザー

- MVP: 作者自身。手元の GPU マシンで Forge / A1111 とローカル LLM を動かしている個人
- 将来: 同様の環境を持つ個人。インストールは `npx` か単一パッケージで済むこと

## ユーザーストーリー（MVP）

1. `drawroid` を起動し、ブラウザで Web UI を開く。初回は LLM とバックエンドの接続先を設定する
2. 「夕暮れの海辺に立つ白いワンピースの少女、アニメ調、10回まで」と依頼する。止める条件の変換結果を確認して開始する
3. 席を外す。その間、考える役がパラメータを決め、Forge が生成し、見る役が評価し、次を決める
4. 戻ってきて Web UI で各回の画像と判断の理由を眺める。途中で「もっと逆光で」と口を出すと、次の回から反映される
5. ループが止まる（意図どおりと判断された / 10回に達した）。人間は気に入った1枚を選ぶ
6. drawroid はジョブの経過から好みを蒸留して記憶に溜める。次の依頼では、それが効いた状態から始まる
7. 人間は記憶を読み、違っているものを直す

## スコープ外（非ゴール）

- マルチユーザー / 認証 / 公開サーバとしての運用
- クラウドへのデプロイ・コンテナ化
- 画像生成の実装そのもの（SD を自前で動かさない。既存バックエンドの API を叩く）
- モデル・LoRA の学習
- 動画生成
